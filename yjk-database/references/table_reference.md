# YJK数据库表字段参考

本文档汇总 `dtlModel.docx` 中主要业务表的字段含义，并与仓库内样本数据库的实际结构保持一致。

配合阅读：

- `database_baseline.md`：参考库基线、最小建模表、样本校验结果
- `table_relationships.md`：表间主引用链、`SectID` / `GridID` / `JtID` 等关系说明

## 全局字段约定

| 字段 | 说明 |
|------|------|
| `ID` | 业务主编号，很多表用于跨表引用；起始值应以 `dtlmodel.db` 实测最小值为基准 |
| `idNew` | 新编号体系，仍需通过参考库提取最小值，不应写死 |
| `No_` | 表内顺序号或层内编号，不具备全局唯一性 |
| `StdFlrID` | 标准层引用键 |
| `SectID` | 截面或类型定义引用键 |
| `GridID` | 网格引用键 |
| `JtID` / `Jt1ID` / `Jt2ID` | 节点引用键 |
| `ParaVal` | 参数值，必须结合附录编号解释 |

## 版本字段别名

部分 YDB 样本与 `dtlModel.docx` / `dtlmodel.db` 的字段命名存在版本差异，校验和读写时需要兼容：

| 参考命名 | 变体命名 | 典型表 |
|----------|----------|--------|
| `No_` | `No` | `tblLoadSeg`, `tblLoadSect` |
| `Type_` | `Type` | `tblLoadSeg` |
| `ElementID_` | `ElementID` | `tblLoadSeg` |

说明：

- 这些变体字段表达的业务语义相同，但不能假设所有库都采用同一命名
- `tblGroup.idNew` 在部分样本中为 `BLOB`，不是单个整数
- `tblLoadSeg` 在部分版本中同时带有 `SectID` 和 `idDef`，分别参与荷载定义表的多分支引用

## 最小建模重点表

当前仓库参考库 `dtlmodel.db` 的非空表为：

`tblStdFlr`、`tblStdFlrPara`、`tblFloor`、`tblJoint`、`tblGrid`、`tblAxis`、`tblColSect`、`tblColSeg`、`tblBeamSect`、`tblBeamSeg`、`tblProjectPara`、`tblProperty`

如果目标库缺少上述表，应优先判定为最小建模不完整。

**偏心符号说明：**
- 直线：遵循右手螺旋法则，大拇指向为起点到终点（垂直x相差小于50时从上到下，其他从左到右），出屏幕方向为正
- 圆弧：沿半径方向，远离圆心为正，靠近为负
- 定位距离（墙洞、悬挑板）：0居中布置，>0左边线距离起点的距离，<0右边线距离终点的距离

## 表之间的关系

### 主要关联关系

1. **标准层体系**: `tblStdFlr` → `tblStdFlrPara`, `tblFloor` → `tblAxis`, `tblGrid`, `tblJoint`
2. **构件体系**: 每种构件都有 `类型表`(如`tblColSect`) → `布置表`(如`tblColSeg`)
3. **索引关系**:
   - 构件布置表通过 `StdFlrID` 关联标准层
   - 构件布置表通过 `SectID` 关联类型定义表
   - 构件布置表通过 `GridID`/`JtID` 关联网格/节点
4. **属性扩展**: `tblProperty` 通过 `ID` 关联任意构件

### 数据流程

```
标准层(tblStdFlr)
    ↓
自然层(tblFloor) → 轴线(tblAxis) → 网格(tblGrid) → 节点(tblJoint)
    ↓
构件类型定义(tblXXXSect) → 构件布置(tblXXXSeg)
    ↓
属性扩展(tblProperty)
```

---

## 注意事项

1. 同层之间的构件编号按构件顺序排列，且唯一。不同层之间的构件编号可以重复。
2. 构件的ID号为全局编号，模型中的构件的ID号具有唯一性。
3. 构件的偏轴距离按照局部坐标系下正向为正值，负向为负值。
4. 构件的HDiff1为构件定位线的起点，HDiff2为定位线的终点。
   - 水平构件：左为起点，右为终点
   - 垂直构件：下为起点，上为终点
5. 次梁截面同主梁截面。
6. 板洞的类型只有矩形、圆形、正多边形三种。
